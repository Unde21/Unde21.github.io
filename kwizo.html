    The project

    Kwizo is our ft_transcendence: a real-time multiplayer quiz, as a web app and an Android app built with Expo, made by a team of four. I was Product Owner and front-end developer. Create quizzes, groups and invitations, host a session with a join code, and play live rounds with streaks, a fastest mode and leaderboards, in five languages.

    What runs here

    • the real Expo app, built for the web from its source
    • the real NestJS backend, in this tab: REST API, JWT auth, Socket.io gateways and the game engine
    • PostgreSQL itself (PGlite, compiled to WebAssembly) with the project’s Prisma migrations
    • data created by the project’s own seed script: 134 users, 36 groups, 30 quizzes
    • OAuth sign-in (42, Google, GitHub) needs real OAuth apps, so the demo uses email accounts

    Under the hood

    The backend is compiled with tsc and bundled for the browser, with a virtual http module that Express and Socket.io attach to. The app’s requests to its API never leave the tab: a small XMLHttpRequest bridge hands them to that server, and Socket.io uses long-polling over the same bridge. The extra players are bots following the protocol of the team’s realtime test client.
